# 계속 새로 쓰는 장치 — refresh.py

이 사이트의 숫자는 손으로 적은 것이 아닙니다. 매일 남긴 리추얼 기록 파일에서
`refresh.py`가 직접 세어 넣습니다. 과정이 끝난 뒤에도 **기록 파일만 새로 얹고 한 번 돌리면**
사이트의 숫자와 문단 후보가 그날 기준으로 다시 만들어집니다.

## 세 단계로 끝납니다

```
1) 새 기록 파일 세 개를 이 폴더에 둔다   ritual-history-2026-10-20.txt
                                        출석.txt · 제출현황.txt  (숫자만 고쳐 쓰면 된다)
2) 장치를 돌린다
   python3 refresh.py ritual-history-2026-10-20.txt --attendance 출석.txt --progress 제출현황.txt --html index.html
3) 바뀐 index.html 을 올린다            (GitHub Pages면 그대로 커밋)
```

파이썬 3.8 이상만 있으면 됩니다. 설치할 라이브러리가 없습니다.

## 돌리면 이런 화면이 나옵니다

```
$ python3 refresh.py ritual-history-2026-09-21.txt --attendance 출석.txt --progress 제출현황.txt --html index.html
기록 26일 (2026-08-11 ~ 2026-09-21, 약 6.0주)
  · site-data.json
  · paragraph-candidates.md
  · index.html 숫자 32곳 갱신
실천 83% · 회복 100% · 동료 피드백 194건 · 출석 90% · 승인 11/13
```

## 무엇이 만들어지나

| 파일 | 내용 |
|---|---|
| `site-data.json` | 사이트에 박히는 숫자 전부 (기간·기록일수·실천율·회복율·연속기록·동료 피드백 수·출석·승인 현황) |
| `paragraph-candidates.md` | 사이트 본문에 넣을 **문단 후보** 6종. 승인한 문장만 사이트에 올립니다. |
| `index.html` | `--html`을 줬을 때만. 숫자가 박힌 자리를 새 값으로 갈아끼웁니다. |

## 숫자가 갈아끼워지는 방식

사이트 HTML에서 숫자가 들어갈 자리에는 이름표가 붙어 있습니다.

```html
<span data-stat="bounce_rate">100</span><span class="u">%</span>
```

장치는 `data-stat="이름"`이 붙은 자리만 찾아서 그 안의 값을 바꿉니다.
**이름표가 없는 글은 장치가 건드리지 않습니다.** 그래서 이야기 본문은 그대로 남고
숫자만 갱신됩니다. 지금 사이트에는 이런 자리가 32곳 있습니다.

## 각 숫자를 어떻게 세는지

| 이름 | 세는 방법 |
|---|---|
| `total_days` | 기록이 하나라도 있는 날의 수 |
| `morning_days` / `evening_days` | 아침 칸 / 마무리 칸을 낸 날의 수 (칸만 열고 비워 둔 날도 낸 것으로 센다) |
| `act_rate` | 마무리 기록의 `강점 행동`이 적힌 날 중 `실천했다`+`일부 실천했다` 비율 |
| `bounce_rate` | `못 했다`로 적은 날 **다음 기록일**에 다시 실천으로 돌아온 비율 |
| `longest_streak` | 기록이 이어진 가장 긴 구간(사흘 이상 비면 끊어진 것으로 봄) |
| `peer_feedback` | `동료 n가 말해 준 내 장점` + `동료 n가 나눈 감사` 줄의 총 개수 |
| `breath_total_min` | 아침 기록 `호흡`에 적힌 분의 합계 |
| `att_rate` | 「내 출석 기록」의 출석 ÷ 수업일 (공휴일은 수업일에서 뺀다) |
| `att_sick` / `att_absent` | 병가 / 무단결석 — 합치지 않고 따로 보여 준다 |
| `prg_approved` / `prg_total` | 「내 제출 현황」의 마스터 승인 과제 수 ÷ 전체 과제 수 |

`회복율`은 **못 한 날을 지우지 않고 남겼기 때문에** 셀 수 있는 숫자입니다.
기록에서 실패한 날을 지우면 이 숫자는 계산되지 않습니다.

## 두 가지 약속

**같은 입력이면 항상 같은 결과가 나옵니다.**
장치는 실행 시각을 결과에 넣지 않습니다. `based_on`(기준일)은 컴퓨터 시계가 아니라
**입력 기록의 마지막 날짜**입니다. 그래서 같은 파일로 몇 번을 돌려도 결과가 한 글자도
달라지지 않습니다. 확인하는 법:

```
python3 refresh.py 기록.txt --attendance 출석.txt --progress 제출현황.txt --out 시험1
python3 refresh.py 기록.txt --attendance 출석.txt --progress 제출현황.txt --out 시험2
diff -r 시험1 시험2      # 아무것도 출력되지 않아야 정상
```

**가려진 값은 버립니다.**
기록 안에 `(이름 가림)`이 들어간 항목은 숫자 계산에도, 문단 후보에도 넣지 않습니다.
남의 실명이 사이트로 새어 나가지 않게 하려는 장치입니다.

## 출석·제출 현황 파일의 모양

두 파일은 `- 항목: 숫자` 한 줄짜리입니다. 손으로 고칠 수 있게 일부러 단순하게 뒀습니다.
**두 파일은 선택입니다.** 없이 돌리면 그 출처의 숫자만 빠지고 나머지는 그대로 나옵니다.

```
# 내 출석 기록
- 수업일: 29
- 출석: 26
- 지각: 0
- 병가: 3
- 무단결석: 0
```

병가와 무단결석은 **따로 셉니다.** 아파서 못 간 날과 그냥 안 간 날은 다른 사실이라,
둘을 합쳐 '결석'으로 뭉개지 않습니다. (`결석:` 이라고만 적으면 무단결석으로 읽습니다.)

```
# 내 제출 현황
- 전체 과제: 13
- 마스터 승인: 11
- 진행 중: 12
- 현재 주차: 5
```

## 리추얼 기록 파일의 모양

내보내기 텍스트를 그대로 넣으면 됩니다.

```
## 2026-09-04
[아침]
- 호흡: 5분
- 오늘 지킬 강점·가치: 안 좋은 감정 못된 감정 버리고 싶다.
[마무리]
- 강점 행동: 실천했다
- 나에게 남기는 말: 아 너무 칭찬한다. 잘했다.
```

`## 날짜`로 하루가 시작하고, `[아침]`/`[마무리]`로 칸이 갈리고, `- 항목: 값` 한 줄이
기록 하나입니다. `#`로 시작하는 머리말 줄은 건너뜁니다.

JSON도 그대로 받습니다.

```json
{
  "days": [
    {
      "date": "2026-09-04",
      "open":  ["호흡: 4.65분", "오늘 지킬 강점·가치: 끈기", "강점이 드러난 일화: …"],
      "close": ["강점 행동: 실천했다", "나에게 남기는 말: 아 너무 칭찬한다. 잘했다."]
    }
  ]
}
```

`date`만 필수입니다. `open`/`close`는 없어도 그날은 그냥 비어 있는 날로 셉니다.
줄의 형식은 `항목 이름: 값` 한 줄입니다.

## 문단 후보는 자동으로 올라가지 않습니다

`paragraph-candidates.md`는 **후보**일 뿐입니다. 장치가 사이트 본문을 스스로 고치지 않습니다.
읽어 보고 쓸 문장을 골라 직접 옮겨 넣습니다. 숫자는 기계가, 문장은 사람이 책임집니다.

## 이 폴더에 있는 것

```
refresh.py                        장치 (본체)
ritual-history-2026-09-21.txt     입력 — 리추얼 기록 (.json 도 그대로 읽는다)
출석.txt                          입력 — 내 출석 기록
제출현황.txt                       입력 — 내 제출 현황
index.html                        사이트 (혼자 열리는 완전한 HTML)
artifact-page.html                같은 사이트의 Artifact 발행용 본문
                                  숫자 이름표가 똑같이 32곳 들어 있어
                                  `--html artifact-page.html` 로도 갱신됩니다
out/site-data.json                마지막 결과 — 숫자
out/paragraph-candidates.md       마지막 결과 — 문단 후보
문서/이력서.md 자기소개서.md 경력기술서.md
```
